# Ren'Py / Godot common subset — specification v0.1

[Version française](SPEC-sous-ensemble-renpy.md)

## 1. Principle

- **Ren'Py is the reference.** Every script in the subset is a valid Ren'Py script. It must play out the same way in the Godot player: same lines, same choices, same variables, same order.
- **Shared scripts live in `game/story/`.** They are generated from the scene sheets in `contenu/` by `tools/fiches.py` (see [contenu/README.md](contenu/README.md)), which only produces this subset: do not edit them by hand. Godot only reads this folder. Ren'Py-specific code (`gui.rpy`, `screens.rpy`, `options.rpy`, gallery screens, etc.) stays in `game/`, outside `story/`.
- **Anything outside the subset is an error.** The Godot compiler reports it as `file:line`, so it also works as a linter for writers.

## 3. Supported statements

### Top level (no indentation)

| Statement | Syntax | Notes |
|---|---|---|
| Character | `define lena = Character(_("Léna"), color="#c8a2ff")` | The name is a string, or `_("…")` to have it translated. Accepted arguments: `color` (or `who_color`), `what_color`. |
| Constant | `define x = expression` | Re-evaluated on every load, as in Ren'Py. |
| Variable | `default x = expression` | Saved. A variable added later is initialised when a save is loaded. |
| Image | `image lena triste = "images/other_name.png"` | Optional: files in `game/images/` are declared automatically. |
| Label | `label name:` | At the end of the block, execution continues with the next label of the same file. The end of a file acts as `return`. |

### Inside a label

| Statement | Syntax | Notes |
|---|---|---|
| Narration | `"Text"` | May end with `id identifier`, like a line. |
| Line | `lena "Text"` or `"Any name" "Text"`, optionally followed by `id identifier` | The `id` links the line to its translations (section 6) and must be unique. |
| Background | `scene rue_nuit [with dissolve]` | `scene` alone clears the screen. Removes every character. |
| Character | `show lena sourire [at right] [with dissolve]` | Positions: `left`, `center`, `right`, `truecenter`. Without `at`, keeps the previous position of the same tag (`center` by default). |
| Hide | `hide lena [with dissolve]` | |
| Transition | `with dissolve` | Transitions: `dissolve`, `fade`, `None`. |
| Menu | see below | An optional line before the choices. A choice may have `if condition`. |
| Condition | `if` / `elif` / `else` | |
| Loop | `while condition:` | No `break` or `continue`. |
| Jump | `jump label`, `call label`, `return` | `return` without a value. |
| Assignment | `$ x = …`, `$ x += …`, `$ x -= …`, `$ x *= …` | |
| Video | `$ renpy.movie_cutscene("videos/scene.webm")` | See section 5. |
| Map | `$ naviguer("ville")`, `$ naviguer("immeuble", "hall")` | Shows the navigation map (section 5b): the player picks a location, which jumps to its scene. The optional second argument is the location the player is in, highlighted on the map. |
| Pause | `pause`, `pause 1.5`, `$ renpy.pause(1.5)` | `pause` alone waits for a click. |
| Audio | `play music "audio/theme.ogg" [fadein 1.0] [fadeout 1.0] [loop\|noloop]` | Channels: `music`, `sound`, `audio`. |
| Stop audio | `stop music [fadeout 1.0]` | |
| Misc | `pass`, `window show\|hide\|auto`, `# comment` | `window` is ignored by Godot. |

```renpy
menu:
    lena "Alors… tu restes un peu ?"

    "Lui faire confiance":
        $ relation_lena += 2
        jump ch01_sc03a

    "L'interroger sur la photo" if indice_photo:
        jump ch01_sc03b
```

A choice whose condition is false is not displayed. A menu with no visible choice is skipped, as in Ren'Py.

### Text

- `[variable]` inserts the value of a simple variable. `[[` produces a literal bracket.
- Tags converted to Godot BBCode: `{b}`, `{i}`, `{u}`, `{s}`, `{color=#hex}`. The others (`{w}`, `{p}`, `{size}`, etc.) are ignored by Godot.

## 4. Expressions

They are translated from Python to Godot's `Expression` class.

- **Allowed:** numbers, strings `"…"` or `'…'`, `True`, `False`, `None`, lists `[…]`, `+ - *`, comparisons, `and`, `or`, `not`, `in`, parentheses, the functions `min`, `max`, `abs`, `str`, `int`, `float`.
- **Forbidden:** `/`, `//` and `%` (results differ between Python and Godot), dotted access (`persistent.x`, `renpy.random…`), `is`, conditional expressions `a if c else b`, `lambda`, comprehensions.
- Every variable used must be declared with `default` or `define`, or assigned with `$`.

## 5. Media

- **Images:** `game/images/` (subfolders allowed), as PNG, JPG or WebP. The lowercase file name gives the image name; spaces separate the tag from the attributes, as in Ren'Py.
- **Videos:** the script references the `.webm`, which Ren'Py plays. Godot plays the `.ogv` (Ogg Theora) with the same name. `python3 tools/convertir_videos.py` generates missing or outdated `.ogv` files.
- **Audio:** prefer Ogg Vorbis `.ogg`, which both engines play. Godot does not play Opus.
- **Gallery:** `game/galerie.json`, generated from the `galerie` field of the scene sheets, lists the entries. Godot reads it in `engine/gallery.gd`, Ren'Py in `game/galerie.rpy`. Each entry is unlocked once its label has been reached (`renpy.seen_label` on the Ren'Py side). It shows either images one by one on a black background, or a video; a click moves to the next image or stops the video. Format:

```json
{"entrees": [
  {"titre": "La confiance de Léna", "label": "ch01_sc03a", "vignette": "lena rougit",
   "video": "videos/lena_scene_01.webm"},
  {"titre": "Le secret de Léna", "label": "ch01_sc03b", "vignette": "lena serieuse",
   "images": ["appartement_soir", "lena serieuse"]}
]}
```

The tests check that every label, image and video it mentions exists.

### 5b. Navigation: maps, rooms and character presence

`game/navigation.json`, generated from the bible (`cartes`, `presence`), describes the navigation maps. Godot reads it in `engine/navigation.gd`, Ren'Py in `game/navigation.rpy`, which also defines the `naviguer()` function and the `carte` screen. `$ naviguer("ville")` (scene sheet: `carte: ville`) does the same in both engines:

1. the location of every character is recomputed: the first `presence` rule whose condition is true gives the location, stored in the variable `lieu_<character>` (declared by `default lieu_lena = ""` in the generated script), so the scenes can test it;
2. the map waits for the player to choose a location, which jumps to its label. A location may instead open a sub-map (the rooms of a building), displayed in place, with a "← parent map" button.

Two layouts: `"affichage": "carte"` is a full-screen image with the locations placed on it (`x`, `y` in percent); `"pieces"` is a row of round room icons at the bottom left of the screen, over the current scene or the map image (the room name appears on hover; a round icon of the parent map exits the building). In both, every location shows the characters present there (their `avatar` image, or their name in their colour); a location that opens a sub-map shows the characters of all its rooms; the location given as second argument of `naviguer` is highlighted ("you are here"). A location whose `si` is false is not shown. During any scene whose label plays in a room of a `pieces` map (`"scenes"`: label → location), the row stays on screen without clicks, above the dialogue box (Ren'Py: overlay screen `pieces_permanentes`; Godot: same node in overlay mode). Conditions (`si`) use the expression subset (section 4). Format:

```json
{"cartes": {
   "ville": {"titre": "La ville", "affichage": "carte", "image": "carte_ville", "parent": "",
             "lieux": [{"lieu": "immeuble", "nom": "L'immeuble", "icone": "", "x": 50, "y": 36,
                        "label": "", "carte": "immeuble", "si": ""},
                       {"lieu": "cafe", "nom": "Le café", "icone": "", "x": 80, "y": 66,
                        "label": "ch02_cafe", "carte": "", "si": "moment != \"soir\"", "temps": {"creneaux": 1}, "raccourci": false}]},
   "immeuble": {"titre": "L'immeuble", "affichage": "pieces", "image": "", "parent": "ville",
                "lieux": [{"lieu": "hall", "nom": "Le hall", "icone": "icone_hall", "x": 50, "y": 50,
                           "label": "ch02_hall", "carte": "", "si": "heure < 2"}]}},
 "raccourcis": [{"lieu": "appartement_pere", "nom": "L'appartement de mon père", "carte": "appartement", "label": "",
                 "si": "moment != \"soir\"", "temps": null, "raccourci": true, "carte_origine": "immeuble"}],
 "scenes": {"ch02_hall": "hall", "ch02_cafe": "cafe"},
 "personnages": {
   "lena": {"nom": "Léna", "couleur": "#c8a2ff", "avatar": "lena avatar", "variable": "lieu_lena",
            "presence": [{"lieu": "appartement_lena", "si": "heure == 0"}, {"lieu": "cafe", "si": ""}]}}}
```

Sub-maps nest without limit; each map shows a breadcrumb of its parent maps (clickable, no cost). An entry's `temps` ({creneaux: n} or {jours: n}) is paid when the entry is clicked, by running the generated time labels at once (Ren'Py: `renpy.call_in_new_context`; Godot: `Interpreter.apply_costs`), so the conditions of the sub-map opened are evaluated after the trip; the route explorers do the same. `raccourcis` lists the entries flagged `raccourci`, offered on every map that does not hold the location itself. A map with no reachable location is skipped, like a menu with no visible choice (`verifier` reports it). Titles, location names and character names are translated like the other texts (`translate strings`). The map is an interaction like a menu: rollback and saves work on it; a save reopens the map that was requested, not the sub-map that was open.

### 5c. Character sheets: gauges, skills and relationships

`game/personnages.json`, generated from the bible (`jauges`, `competences`, `relations` of each character), describes the "Characters" screen of the game menu. Godot reads it in `engine/characters.gd` and shows it in `engine/ui/characters_page.gd`, Ren'Py in `game/personnages.rpy` (screen `personnages`, button "Characters" in the game menu). Each gauge or skill reads one variable of the game, `<character>_<name>`, declared by `default` in the generated script and handled like any other variable (saves, rollback, `$ x += 1`, conditions). Format:

```json
{"personnages": {
   "lena": {"nom": "Léna", "couleur": "#c8a2ff", "avatar": "lena avatar",
            "jauges": [{"variable": "lena_relation", "nom": "Relation", "min": 0, "max": 10,
                        "paliers": [{"des": 0, "nom": "distante"}, {"des": 6, "nom": "amie"}]}],
            "competences": [{"variable": "lena_photographie", "nom": "Photographie", "min": 0, "max": 5,
                             "paliers": []}],
            "relations": [{"variable": "lena_karim", "avec": "karim", "nom": "Karim", "couleur": "#f2b45c",
                           "min": 0, "max": 10, "paliers": [{"des": 4, "nom": "collègues"}]}]}}}
```

A relationship is one variable shared by two characters: it is listed on both sheets, `avec` naming the other character, whose name and colour are used unless the relationship has its own name. Both engines draw the same thing: a column of tabs on the left, one per character (round avatar or a disc in the character's colour, and the name, which takes that colour once the tab is open), then the open character's sheet: avatar and name, and one row per gauge, skill and relationship with a bar from `min` to `max`, the value over the maximum, and the name of the highest `paliers` threshold reached (none below the first threshold). Names of gauges, skills, relationships and levels are translated like the other texts (`translate strings`). The screen only exists during a game, since it reads the game's variables. The tests check that every variable it mentions is a numeric `default` of the script.

### 5d. Time: slots and days

`game/temps.json`, generated from the bible (`temps`), describes the time model: `{"creneaux": ["matin", "midi", "soir"], "jours": true, "semaine": [...], "date": true, "mois": [...], "epoques": ["present", "passe"]}`. The state lives in ordinary variables of the generated script, declared by `default`, so saves, rollback and conditions need nothing special: `creneau` (rank), `moment` (slot name), `jour`, `jour_semaine` and `jour_semaine_rang`, and with a calendar `jour_mois`, `mois`, `annee`, `evenement_<name>`, `epoque`, plus internal `temps_*` and `epoque_<era>_*` variables. Only generated labels change them, all written in the subset (no division or modulo: month lengths come from an `if` chain, leap years from a counter reset every four years, 2100, 2200 and 2300 excepted): `temps_avancer` (next slot, then `temps_jour_suivant` after the last one), `temps_jour_suivant` (day counter, weekday, calendar), `temps_calculer_noms` (slot and weekday names, events), `temps_calculer_mois`, `temps_sauter_jours` and `temps_sauter_mois` (loops on `temps_saut`, a `jump` back to the same label), and one `temps_epoque_<era>` per era (the current date is stored in `epoque_<era>_*`, the target era's date restored). The scene sheets reach them through the `temps` element: `call temps_avancer` repeated, guarded by `if moment != "…"` for a named slot; `$ temps_saut = n` then a call for day and month jumps; direct assignments (`$ annee = …`, `$ jour = …`, then `call temps_calculer_noms`) for a date known in advance; `call temps_epoque_<era>`. A location with backgrounds per slot or era compiles to an `if moment == "…"` / `if epoque == "…"` chain with the first image as fallback. During a game both engines show "Jour 2 · mardi · matin" or "vendredi 16 octobre 2026 · soir" at the top right (Ren'Py: overlay screen `temps_permanent` in `game/temps.rpy`; Godot: `engine/temps.gd` and a label in the player), hidden while a map is open; slot, weekday and month names are translated like the other texts. The Godot tests compare 800-day and 3-month jumps of the generated calendar with Godot's own calendar, and check that an era resumes where it was left.

## 6. Translations

Ren'Py's translation system, restricted as follows; the Godot player reads the same files.

- **Languages:** `game/langues.json`, generated from the bible (`langues`), lists the language of the sheets and the translations: `{"source": {"code": "fr", "renpy": "french", "nom": "Français"}, "traductions": [{"code": "en", "renpy": "english", "nom": "English"}]}`. Ren'Py reads it in `game/langues.rpy`, Godot in `engine/langues.gd`.
- **Translated lines:** `game/tl/<language>/**/*.rpy`, generated by `tools/fiches.py`. A `translate <language> <id>:` block holds exactly one line (narration or character): the translation of the line that carries `id <id>`.

```renpy
translate english ch01_sc02_14e17bdd:

    # lena "Je ne pensais pas que tu viendrais."
    lena "I didn't think you'd come."
```

- **Texts:** `translate <language> strings:` blocks, with `old "…"` / `new "…"` pairs, translate character names (declared with `_()`), menu choices and gallery titles.
- **Ren'Py only:** `translate <language> python:` and `translate <language> style:` blocks only affect the Ren'Py interface, and Godot ignores them. Any other statement in `game/tl/<language>/` is an error in Godot.
- **Default language:** the language of the sheets is Ren'Py's default language (`config.default_language`). Its interface texts are translated in `game/tl/<language>/` (French is provided, taken from Ren'Py's own translations); in English, Ren'Py's interface texts are the originals. The Godot interface texts are in `engine/ui/traductions_interface.gd`.
- **Choosing a language:** Preferences → Language, in both engines. On first launch, the game uses the system language if it is available, otherwise the language of the sheets.
- A line or a text without a translation is shown in the original language.

## 7. Outside the subset

These remain reserved for Ren'Py files located outside `game/story/`:

- `python:` and `init python:` blocks;
- `screen`, `call screen`, `transform` and ATL, `style`, `nvl`, `voice`, `queue`, `layeredimage`, `for`;
- `translate` in `game/story/`: translations go to `game/tl/<language>/` (section 6);
- named menus, `set`;
- image attributes in dialogue lines (`lena sourire "…"`): use `show` before the line;
- `show … behind | zorder | onlayer | as`;
- multi-line strings;
- `renpy.*` except `movie_cutscene` and `pause`, as well as `persistent`; the only other function allowed after `$` is `naviguer("map")`.

## 8. Known differences in the Godot player

- **Saves:** the position is stored as "label + instruction number". Editing a label before the saved point can shift where the game resumes; Ren'Py is more tolerant. A variable added later takes its `default` on load in both engines. Names that disappear are handled by `game/renommages.json` (bible: `renommages`): Godot moves the saved value to the new variable and resolves renamed labels (position and call stack) when it loads a state; Ren'Py uses `config.label_overrides` and an after-load callback (`game/sauvegardes.rpy`). Chained renames apply in the declared order.
- **Godot player features:** main menu, game menu, history (250 lines), rollback (128 interactions), skip limited to already-read text, auto-forward, 5 pages of 6 slots with thumbnails, quick save (F5 / F9), preferences and gallery.
- **Rollback:** it does not survive loading a save (Ren'Py keeps it in the save). There is no rollforward either.
- **Preferences missing in Godot:** "keep skipping after choices", accessibility. The auto-forward delay is computed more simply than in Ren'Py.
- **Already-read text:** a line is identified by its `id` when it has one (the same in every language), otherwise by its label, its speaker and its text. Editing it makes it "unread" again, as in Ren'Py.
- **Gallery:** Ren'Py adds it to the main menu (a "Gallery" button in `screens.rpy`, translated like the rest of the interface).
- **Navigation maps:** the Ren'Py screen is named `carte` (`navigation` is Ren'Py's main-menu screen). The two engines share the layout (positions in percent, round room icons at the bottom left); fonts and image scaling may differ slightly. Ren'Py crops the icons with `gui/navigation_rond.png`, Godot with a textured polygon.
- **Changing language during a game:** Godot redisplays the current line, menu or map in the new language at once. Earlier lines stay in the history in the language they were shown in.
- **`with` on its own:** in Godot, transitions only apply on a `scene`, `show` or `hide` line. A standalone `with` line has no visual effect.
- **`show`:** the image name must exist as written. Godot does not resolve partial attributes the way Ren'Py does.
- **`fade`:** Godot fades in from black, while Ren'Py fades to black and back.
- **Sprites:** displayed at their native size, scaled down only if they are taller than the screen.

## 9. Commands

| Action | Command |
|---|---|
| Play (Godot) | `godot --path .`, or open `project.godot` in the editor and press F5 |
| Play in a language (Godot) | `godot --path . -- --langue=en` (this session only; the saved preference is unchanged) |
| Autoplay | `godot --path . -- --choices=1,0` (rank among the displayed choices) |
| Scripted UI run | `godot --path . -- --actions=start,advance,menu:characters,character:lena,back,quit` (actions listed in `_run_action`, `engine/vn_player.gd`) |
| Godot tests | `godot --headless --path . --script res://tests/run_tests.gd` |
| Route report | `godot --headless --path . --script res://tools/routes.gd` |
| Play (Ren'Py) | `$RENPY_SDK/renpy.sh .`, or from the launcher |
| Ren'Py lint | `$RENPY_SDK/renpy.sh . lint` |
| Ren'Py tests | `$RENPY_SDK/renpy.sh . test --overwrite-screenshots` (screenshots in `tests/screenshots/`) |
| Placeholder media | `.venv/bin/python tools/fiches.py provisoires` |
| Translation file | `.venv/bin/python tools/fiches.py traduire en` |
| Videos for Godot | `python3 tools/convertir_videos.py` |

**Ren'Py side (already done):** the interface was generated at 1920×1080 with the launcher's hidden command, then completed with `gui_images` (normal and "small phone" variant). The template `script.rpy`, which redefined `label start`, was removed. To regenerate it:

```sh
SDK=$RENPY_SDK
$SDK/renpy.sh $SDK/launcher generate_gui "$PWD" --width 1920 --height 1080 --accent "#b48cff" --template $SDK/gui --start
RENPY_VARIANT="small phone" $SDK/renpy.sh . gui_images
$SDK/renpy.sh . gui_images
rm game/script.rpy
```

In a Ren'Py test, `advance` also interrupts a playing video, like a player's click. The `video_seule` test therefore checks WebM playback without a simulated click.

**Export:**

- Godot: add `*.rpy, *.json` to the "non-resource files" filters and exclude `*.webm`.
- Ren'Py: `*.ogv` and `*.import` are excluded with `build.classify` (already set up in `game/options.rpy`).
